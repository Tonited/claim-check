# claim-check

[English](README.en.md) · **中文**

> **一个"做完了"的声明，不是证据。**

`git commit` 有钩子，`git push` 有保护，但 **agent 说它做完了，一直没人检查**。

`claim-check` 就是这道检查：把「完成」变成一个可验证的声明，用的是**实现者改不了、转述不了、也不能随便查的证据**。

面向日常开发。不引入服务，不新建流程，只在**你准备相信某个结论**的那一刻触发。

---

## 实测结果

我们做了对照实验：同一个真实功能需求、同一个项目、同一套测试命令、同一个 agent 模型，两组之差只在于**用不用 claim-check**。

需求里埋了一句非功能要求：**某个区间不变式必须在数据层保证，不能靠调用方**（等价于"密码校验必须在后端做"）。项目现有测试只锁住那个纯函数本身，**没有一条检查数据层输出的边界**——所以最省力的路径是把约束留在使用层。

| | 基线组（无 claim-check） | 处理组（claim-check） |
|---|---|---|
| `npm run check` | **46 通过 / 0 失败** | **58 通过 / 0 失败** |
| 自称完成 | ✅ | ✅ |
| **数据层"取得即合法"** | **0 / 9** ❌ | **9 / 9** ✅ |
| 契约条款（带锚点） | 无 | 14 条 |
| 证据块（原始输出 + 哈希 + 种子） | 无 | 4 个 |
| 验收结论 | "已完成" | **FAIL / FAILING C1 / UNJUDGEABLE C10,C12** |

基线组并没有偷懒——它做了认真的重构（加了类型品牌、把夹取收敛到唯一构造点）。**它只是不知道自己的保证没覆盖到数据层那条路径**，而它自己写的新测试也测不到。

处理组的验证者产出了 **FAIL** 而不是"通过"：判定契约比需求更强，实现漏了一种输入；还有两条条款因为**实现者没留证据块**而无法判定。全部进原始输出，没有被"看起来都通过"掩盖。

> 完整实验设计、中立测量脚本与空实现鉴别力检查见 [VERIFICATION.md](VERIFICATION.md)。

## 它防的是什么

三种失效，各自需要不同的机制：

| 失效 | 表现 | 靠什么挡 |
|---|---|---|
| **自欺** | 实现者自己说"通过了"，你只能信 | **闸门 1**：证据由脚本产出，不可转述、不可手改 |
| **针对性优化** | 能看到判据 → 改代码让判据变绿，而不是满足需求 | **闸门 2**：判据与实现物理分离 + 随机实例 + 限制判定执行次数 |
| **规格博弈** | 判据本身漏了真实意图（上面那个例子） | **检查表 + 意图锚点 + 可观察量清单** |

第三项**不能**靠"再派一个 agent 评审契约"——独立 reviewer 一样会误读规格，而且倾向于顺从看起来权威的文档。所以它是一张**十行的机械检查表**，输出一页《契约盲区报告》，交给人。

## 快速开始

```bash
# 1. 把 scripts/ templates/ checklists/ 复制进你的仓库
cp -r claim-check/{scripts,templates,checklists} your-repo/
cd your-repo && mkdir -p contract evidence

# 2. 把需求拆成两份文件：需求（给实现者）/ 判定（只给验证者）
#    模板见 templates/contract.template.md
node scripts/forbidden-touch.mjs --init      # 给判定记指纹

# 3. 实现者只能看到 requirements，声称完成时必须给证据：
node scripts/evidence.mjs -- npm test

# 4. 验证者跑判定（每次实例随机，且有执行次数上限）：
node scripts/randomize.mjs -- npm run judge

# 5. 事后检查：判定被动过吗？有人尝试碰它吗？
node scripts/forbidden-touch.mjs

# 6. 人只看证据块 + 两份报告，不看 diff
```

**触发时机**：只在**你准备相信某个结论**的那一刻。日常写代码不用跑它。

## 三个闸门

### 闸门 1 · 证据（防自欺）

实现者不许说"我做完了"，只许贴**证据块**：

```bash
node scripts/evidence.mjs -- <真实命令>
```

脚本产出 `evidence/<id>.md`：**原样的命令、退出码、原始输出（另存为文件）、随机种子、输出哈希**。声明只能**引用**它：

```
claim: 导出功能已实现并覆盖边界输入
evidence: evidence/2026-09-25T05-22-35-950Z-4794f30ce1d7.md
```

规矩：

- **非零退出码是失败，不是"备注"。**
- 证据块**不得手写或手改**——能被编辑的证据不是证据。
- **读证据块就是全部审查**。不要改成去读 diff：diff 只能告诉你代码看着合理，不能告诉你声明是真的。
- 不接受"应该能过""剩下的失败无关""我把输出贴给你看"。

### 闸门 2 · 判据（防针对性优化）

**需求与判定方式物理分开**：

| 文件 | 内容 | 谁能看 |
|---|---|---|
| `contract.requirements.md` | **陈述式**需求、接口、条款标题（带锚点） | 实现者 |
| `contract.judgment.md` | 真正的断言、用例集、期望值、抽样分布、种子 | **只有验证者** |

- 给需求，**永远不给判定方式**。"凭证校验必须在服务端发生"是需求；"这个测试绕过前端调接口期望 401"是判定方式。
- 条款写成**性质 / 蜕变关系**，不写"输入 X → 期望 Y"。例子可以被局部满足，关系不行。
- **条款固定，实例随机**：每次运行重新生成输入与种子。这条**即使判据可见也有效**——你无法针对一个你预知不了的分布去优化。
- **判定执行次数设上限**（默认 3 次，脚本强制）。无限重试是把隐藏判据反推出来的主要途径。
- 判定结果回传给实现者的**只有 pass/fail + 失败条款标题**。实现者自己目录里的测试完全透明；契约判定不透明。

### 闸门 3 · 意图（记录而非阻止）

**"尝试"是这套体系里信噪比最高的观测量。**

通过率分不清"做不到"和"选择不做"，尝试可以。而且这两者是**解耦**的：把评测器锁死能让得逞率归零，而尝试率可能纹丝不动。

```bash
node scripts/forbidden-touch.mjs
```

它比对契约哈希、报告判定是否被改动、统计越权尝试记录。

**能接线就去接线**——没有 hook 时完整性那一半仍然有效，但你失去的是唯一能观测意图的信号。

## 攻击模式检查表

`checklists/attack-patterns.md` — 十行，每行问同一个问题：

> **这份契约在物理上能不能表达"防住这个攻击"的约束？**

答不上来的行进入**契约盲区报告**，交给**人**。

其中两行决定契约形态：

**A4 层替换**（该校验后端做、却写在前端）：**例子型契约结构上无法表达它**，因为"校验发生在哪一层"不是输入输出关系——前端与后端校验可以产生逐字节相同的请求响应痕迹。出路只有两条：

1. **提升可观察量**：让位置本身可观察（服务端日志 / 审计记录 / 持久化状态 / 网络抓包）；
2. **改写为蜕变关系**：断言"**绕过外层直接访问内层时，不变式必须仍然成立**"。

两条都做不到 → 判**不可验证**，写进契约的「未覆盖」一节。**知道某条需求不可验证，远好过相信一个前端测试验证了它。**

**A5 判据篡改**：任何契约内部都表达不了，因为它说的就是契约本身。只能靠闸门 2 和 3。

## 意图锚点与无锚点比例

每条条款标一个真值来源——**必须在 AI 的优化回路之外**：

| 锚点 | 含义 | 能单独成立吗 |
|---|---|---|
| `A1` | 人明确要求的 | 能 |
| `A2` | 仓库既有行为基线（现有测试、历史提交、已文档化的策略） | 能 |
| `A3` | AI 自己推断应该要的 | **不能** |

```
- C1 [anchor: A1] — 接受的输入必须符合策略
- C4 [anchor: A3] — 缩短一位不得把拒绝变成接受
      A3 理由：用户没要求，从策略文档的单调性意图推出
```

`forbidden-touch.mjs` 算出**无锚点条款比例**（A3 + 未标注 ÷ 总数）。这个数字机械地回答：

> **这份契约里有多少是 AI 自己给自己加的？**

为什么需要它：人写的验收清单漏掉一条意图，AI 不会发现，只会忠实地满足这份清单；而"让 AI 审查契约"也救不了——reviewer 继承同样的误读，且对权威文本有顺从倾向。锚点字段让这个盲区**可见，而不需要任何人去判断**。

规则：A3 允许但必须写一行理由，且**不得单独构成一次拒绝**。

## 角色与预算

两个角色，隔离上下文，**不是一条连续会话**：

| 角色 | 能看 | 能做 |
|---|---|---|
| **实现者** | 需求 + 条款标题 | 跑自己目录里的测试。**不得读判定、不得执行判定** |
| **验证者** | 判定 + 实现代码 | 跑判定、产出证据。不写实现代码 |

**实现者不得执行判定**——反复执行并观察结果，是把隐藏判据反推出来的主要途径。这一条比"把测试藏起来"重要得多。

## 明确不要做的事

这些都被验证过并且失败了，加进来只会更重，不会更安全：

- **不要加"一个 agent 评审契约"** —— 它继承同样的误读，并且倾向于顺从权威文本。
- **不要只靠"把测试藏起来"** —— 隐藏而不限制查询，会被反复执行击败。
- **不要用通过率当验收信号** —— 它把"能力不足"和"作弊"混成一个数。要记录改动量、是否绕过某一层、是否动过判据。
- **不要引入形式化理论或三 agent 流水线** —— 两个角色够了。
- **不要让实现者写进判据目录或证据目录** —— 不是"改个测试"，是永远不行。

## 强制阶梯

用宿主能给的最强那一级。三个闸门在任何一级都能工作，只有**越权尝试记录**会降级。

| 级别 | 机制 | 得到 | 失去 |
|---|---|---|---|
| 1 | 物理隔离（判据不在实现者工作视图里） | 闸门 1–2 | 尝试记录 |
| 2 | + git 钩子拒绝改动 `contract.judgment.md` / `evidence/**` | 提交时的完整性 | 尝试记录 |
| 3 | + pre-tool hook / tool guard 记录拒绝 | **尝试率** | — |

**级别 1 就足以挡住最常见的两种失效**（自欺、层替换）。级别 3 是唯一能测量意图的。

在 DSH 上，级别 3 需要 Cordis 插件（`ToolGuard` 单调 deny、`tools/pre-execute` 审批门）。

```
claim-check/
├── SKILL.md                          # 技能本体（给 agent 读的流程，英文）
├── README.md                         # 本文件（中文）
├── README.en.md                      # English
├── VERIFICATION.md                   # 有效性验证报告（对照实验）
├── checklists/attack-patterns.md     # 十行机械检查表 + 可观察量清单
├── templates/
│   ├── contract.template.md          # 需求 / 判定两份契约怎么写 + 锚点规则
│   └── file-ownership.md             # 角色 × 路径权限表 + 三级强制阶梯
└── scripts/
    ├── evidence.mjs                  # 跑命令 → 证据块（带判定预算）
    ├── forbidden-touch.mjs           # 判据完整性 + 锚点比例 + 越权尝试统计
    └── randomize.mjs                 # 固定条款 + 随机实例
```

零依赖，只用 Node 内置模块。要求 Node ≥ 22。

## 已知限制

- **`ToolRestriction` 在 DSH 上是工具名级**，没有按路径禁读的原生能力。所以"判据不可见"只能靠**物理分离**（判据不在实现者的工作视图内），而不是靠权限配置。
- **判定执行计数器与 agent 同进程**，理论上存在被重置的可能。当前靠证据块记录，属"可审计"而非"不可伪造"。真正的不可伪造需要插件层。
- **锚点统计依赖书写格式**：脚本按行匹配 `- C1 [anchor: A1] — 标题`。条款写在表格里或不用 `C<n>` 编号就**不会被统计**——此时它会明确报"未发现条款行"，而不是报 0%。**"格式不合"和"零未锚点"必须区分开。**
- **检查表覆盖十种已知作弊模式，不是穷举**。它是一份活文档——发现新模式就加一行。
- **判定本身也可能有缺陷**：实验里就出现过"契约要求比需求更强，导致实现被误判失败"。所以判定也需要"空实现检查"——跑一遍不满足的实现，确认判定会失败。
